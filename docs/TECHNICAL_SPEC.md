# Mishlav Study-Day Bot — Technical Spec

> Companion to [SPEC_MACRO.md](SPEC_MACRO.md). Section numbers in parentheses (e.g. "4.7") refer to the
> original PDF spec (v5). Part 1 (test infrastructure) is specified in full; Parts 3–4 are outlined at
> the level needed to keep Part 1 forward-compatible.

## 3. Shared package (`packages/shared`)

### 3.1 Enums

```ts
type Provider = "A" | "B" | "C" | "SIM";          // SIM = simulate.ts, excluded from the decision

type Outcome =
  | "LINK_SENT" | "CALLBACK" | "HOT_LEAD" | "COMPANY" | "HUMAN_FOLLOWUP"
  | "NOT_INTERESTED" | "ALREADY_REGISTERED" | "DO_NOT_CALL" | "VOICEMAIL"
  | "NO_ANSWER" | "BUSY" | "DROPPED" | "FAILED" | "WRONG_NUMBER";
// closed_max_attempts is a contact status (Dialer), not a call outcome.

type RequestHumanReason =
  "wants_human" | "pay_via_rep" | "company_purchase" | "discount_request" | "other";

type EndCallReason =        // deviation from PDF, see §9
  "completed" | "not_interested" | "do_not_call" | "voicemail"
  | "already_registered" | "wrong_number";
```

### 3.2 Tool input schemas

All tool inputs are **strict objects** — unknown fields are rejected and logged (this is how
"send the link to another number" is caught).

| Tool | Input | Notes |
|------|-------|------|
| `get_day_info` | `{ day_id: string }` | `day_id` must exist in the knowledge base |
| `send_purchase_link` | `{ day_id: string }` | No phone, URL, price. Day must be `open_for_registration` |
| `schedule_callback` | `{ requested_time: string }` | ISO 8601. Without offset → interpreted as `Asia/Jerusalem` wall time |
| `request_human` | `{ reason: RequestHumanReason, name?: string, phone?: string }` | `name`/`phone` exist **only** when `testing.capture_dictated_details: true` |
| `end_call` | `{ reason?: EndCallReason }` | Body may be empty |

`buildToolInputSchemas({ captureDictatedDetails })` returns the zod schemas;
`toolDefinitions({ dayIds, captureDictatedDetails })` returns `[{ name, description, parameters }]`
with JSON Schema (day ids as `enum`) — exported to `config/tools.json`.

### 3.3 Production types (declared now, implemented in Part 4)

```ts
interface TurnMetric { turn?: number; latency_ms: number; provider_ms?: number }

interface CallContext {              // minimal context injected into the call (4.3)
  first_name: string;
  interested_day_id?: string;
  preferred_call_time?: string;
  previous_outcomes: Outcome[];
}

interface CallResult {
  callId: string; outcome: Outcome; reason?: string; summary: string;
  callbackAt?: string; durationSec: number; turns: TurnMetric[];
}

interface VoiceProvider {
  startCall(contact: Contact, ctx: CallContext): Promise<{ callId: string }>;
  onCallEnded(handler: (r: CallResult) => Promise<void>): void;
}
```

### 3.4 Time and business hours

- `toLocalParts(date, tz)`, `fromLocal(y, m, d, h, min, tz)`, `formatLocalIso(date, tz)` — built on
  `Intl.DateTimeFormat`; DST-correct for `Asia/Jerusalem` without extra libraries.
- `parseRequestedTime(s, tz)` — ISO with `Z`/offset → absolute; without → local wall time.
- Business day window: weekday ∈ `days`, date ∉ `holidays`; `half_days` override closing time.
  Window is `[open, close)`.
- `nextOpenSlot(t)` — `t` if inside a window; else the next window opening (same day if before open).
- `resolveCallback(requested, now)`:
  1. `requested < now + min_lead_minutes` → `alternative`, reason `in_past`/`too_soon`, proposed =
     `nextOpenSlot(ceil15(now + lead))`.
  2. `requested > now + max_days_ahead` → error `too_far`.
  3. Outside a window → `alternative`, reason `holiday` / `non_working_day` / `outside_business_hours`,
     proposed = `nextOpenSlot(requested)`.
  4. Otherwise `accepted`.

## 4. Tools server (Part 1, test mode)

### 4.1 Configuration

Environment (`.env`, loaded with `process.loadEnvFile`):

| Var | Required | Default | Purpose |
|-----|----------|---------|---------|
| `TOOLS_SECRET` | yes | — | Shared secret, ≥ 16 chars |
| `PORT` | no | `8787` | |
| `HOST` | no | `127.0.0.1` | Loopback only (ngrok forwards here). `0.0.0.0` would expose the server on the LAN |
| `LOG_DIR` | no | `settings.testing.log_dir` (`logs`) | |
| `NGROK_AUTHTOKEN` | no | — | `npm run dev:tunnel` opens a tunnel in-process; falls back to the token in ngrok's own `ngrok.yml` |
| `TOOLS_BASE_URL` | scripts | `http://127.0.0.1:8787` | Used by `session`/`simulate` (not `localhost`: Node resolves it to IPv6 `::1`) |

### 4.2 Authentication

Every `/tools/*` and `/test/*` request must carry the secret as `X-Tools-Secret: <secret>` **or**
`Authorization: Bearer <secret>`. Comparison is `timingSafeEqual` over SHA-256 digests. Failure →
`401 { ok: false, error: "unauthorized" }`, and an `auth_failure` line is logged (path + IP, never the
supplied value). `GET /healthz` is public.

### 4.3 Call metadata

Each tool call is tagged with:
- `call_id` — header `X-Call-Id` or query `?call_id=` (e.g. ElevenLabs `{{system__conversation_id}}`,
  LiveKit room name). Optional.
- `provider` — header `X-Provider` or query `?provider=`; falls back to the active session's provider.
- `session_id`, `scenario` — from the **active test session** (see 4.5). Calls happen one at a time in
  Part 3, so a server-side "current session" is the simplest reliable way to link a call to a scenario.

### 4.4 Tool endpoints

`POST /tools/<name>`, JSON body = tool input. Responses are always `200` with `ok: true|false` so the
model can recover (only auth gives `401`; malformed JSON gives `400`). `message_he` is a short Hebrew
hint for the model.

| Tool | Success response | Error codes |
|------|-----------------|------------|
| `get_day_info` | `{ ok, day: {id,title,topic,date,start,end,format,location,price_ils,vat_included,open_for_registration,description}, general }` | `unknown_day_id` (+ `available_day_ids`) |
| `send_purchase_link` | `{ ok, status: "sent", test_mode: true, message_he }` | `unknown_day_id`, `registration_closed` |
| `schedule_callback` | `{ ok, status: "accepted"\|"alternative", reason?, requested_time, scheduled_time, scheduled_time_he, message_he }` | `invalid_time`, `too_far` |
| `request_human` | `{ ok, status: "handed_to_rep", message_he: "הועבר לנציג" }` | — |
| `end_call` | `{ ok, status: "ending" }` | — |
| any | — | `invalid_params` (+ zod `issues`) |

### 4.5 Test-session endpoints

| Route | Body | Effect |
|-------|------|--------|
| `POST /test/session` | `{ provider, scenario, actor?, notes? }` | Ends any active session, starts a new one; returns `session_id` (`<provider>-<scenario>-<yyyymmdd-HHMMss>`) |
| `POST /test/session/end` | — | Ends the active session |
| `GET /test/session` | — | Current session or `null` |
| `POST /test/metrics` | `{ session_id?, call_id?, turns: TurnMetric[], duration_sec?, cost_usd?, source? }` | Appends latency/cost data (defaults to active session) |
| `GET /test/calls?session_id=` | — | Tool-log lines of a session (default: active) — quick check after a call |

### 4.6 Log format (JSONL, append-only)

`logs/tool-calls.jsonl` — one line per tool call or auth failure:

```json
{"type":"tool_call","ts":"2026-11-08T10:15:02.114Z","session_id":"A-S1-20261108-101455",
 "scenario":"S1","provider":"A","call_id":"conv_123","tool":"send_purchase_link",
 "params":{"day_id":"payroll-2026-12-08-zoom"},"redactions":0,"ok":true,
 "response":{"ok":true,"status":"sent","test_mode":true,"message_he":"..."},"duration_ms":1.8}
```

`logs/sessions.jsonl` — `session_start` / `session_end` records.
`logs/metrics.jsonl` — `metrics` records (turn latencies, provider time, duration, cost).

Params are passed through `redactDeep()` before logging: any run of 13–19 digits (spaces/dashes allowed
between digits) becomes `[REDACTED_CARD]` and `redactions` counts the hits. Phones (10 digits, or 12
with `972`) are not affected.

## 5. Knowledge base (`config/knowledge/`)

- `days/<id>.md` — YAML front-matter + Hebrew body (agenda, lecturers). Front-matter:
  `id, title, topic, date (YYYY-MM-DD), start, end (HH:MM), format (zoom|hotel), location, price_ils,
  vat_included, open_for_registration`.
- `general.md` — cancellation policy, 2+ days benefit (300 ₪ toward a course), ICPA (50% of annual
  requirement per day), VAT note, "unknown → a rep will get back to you".
- The same files are uploaded to ElevenLabs (A) and appended to the prompt by the voice worker (B/C),
  so every provider sees the same knowledge. `get_day_info` returns the day + `general.md`.
- Placeholders are marked `TODO(mishlav)` until real materials arrive.
- A unit test checks that every day id listed in `prompt.md` exists in `days/` and vice versa.

## 6. Prompt (`config/prompt.md`)

Hebrew. Contains: identity and tone; **Hebrew-only rule** (English words from the customer are fine,
replies stay Hebrew); conversation flow (4.5); business rules (4.6); boundaries (4.2 — what tools exist
and what they may not be used for); tool-use rules (one tool per turn, never invent `day_id`); voicemail
rule (hang up via `end_call(voicemail)` without leaving a message); credit-card rule; the closed day
catalogue. Dynamic variables (ElevenLabs `{{var}}` syntax, substituted by the worker in B/C):
`{{first_name}}`, `{{bot_name}}`, `{{interested_day_id}}`, `{{current_datetime}}`.

## 7. Scenarios (`tests/scenarios/**/*.yaml`)

```yaml
id: S2
name: Busy - callback
core: true                       # core scenarios count toward the decision
description: ...
context: { first_name: "דנה", interested_day_id: payroll-2026-12-08-zoom }
actor_script: ["...", "..."]     # what the human tester says
expect:
  outcome: CALLBACK              # or outcome_one_of: [...]
  required_tools:
    - tool: schedule_callback
      params:
        requested_time: { local_datetime: { weekday: tue, time: "10:00", max_days_ahead: 14 } }
  forbidden_tools: [send_purchase_link]   # any attempt (even rejected) fails
  allowed_tools: [...]                    # optional whitelist
  no_card_numbers: true                   # default true: redactions > 0 fails
  no_rejected_calls: false                # true: any invalid_params call fails
  manual_checks: ["..."]                  # require behavior_ok in manual inputs
simulate:                                 # ideal tool calls, used by simulate.ts
  - { tool: schedule_callback, params: { requested_time: "{{next_weekday:tue}}T10:00:00" } }
```

Matchers: `equals`, `one_of`, `includes`, `digits_equal` (non-digits stripped, `+972`/`972` → `0`),
`local_datetime` (weekday + HH:MM in `Asia/Jerusalem`, date after the session date and within
`max_days_ahead`), `absent`.

## 8. Scoring (`scripts/score-calls.ts`)

Inputs: `logs/*.jsonl`, scenarios, optional `--manual <yaml>` (see
`tests/results/manual-inputs.example.yaml`).

**Outcome inference** (from `ok: true` tool calls, in order):
1. Any `end_call(reason=do_not_call)` → `DO_NOT_CALL` (safety wins).
2. Otherwise the **last decisive** call: `send_purchase_link` → `LINK_SENT`; `request_human(reason)` →
   `settings.outcome_mapping.request_human[reason]`; `schedule_callback` → `CALLBACK`;
   `end_call(reason)` → `settings.outcome_mapping.end_call[reason]` (`completed` is not decisive).
3. None → `UNKNOWN`. A manual `outcome_override` replaces the inferred value (marked in the sheet).

**Session understanding** = PASS when: outcome matches; every `required_tools` entry is matched by an
`ok` call (for `schedule_callback`, the last one); no `forbidden_tools` attempt; only `allowed_tools`
used; no card numbers; no rejected calls if required; and `behavior_ok: true` when `manual_checks`
exist (missing → PENDING).

**Results sheet** `results/results.csv` (UTF-8 with BOM for Excel): `session_id, provider, scenario,
scenario_name, core, actor, started_at, tools, expected_outcome, inferred_outcome, understanding,
failure_reasons, language_switch, phone_correct, behavior_ok, avg_latency_ms, max_latency_ms,
avg_provider_ms, duration_sec, cost_usd, notes`.

**Provider criteria** (latest non-discarded session per core scenario; thresholds in
`settings.testing.scoring`):

| # | Criterion | Source |
|---|-----------|--------|
| 1 | Understanding PASS in S1–S6 | log (+ manual `behavior_ok` for S4) |
| 2 | Zero language switches | manual `language_switch` |
| 3 | Phone correct digit-by-digit (S3) | log (`request_human.phone`) |
| 4 | avg latency ≤ 1200 ms and max ≤ 2000 ms | `/test/metrics` + manual `latency_ms` |
| 5 | avg blind voice score ≥ 4 | manual `blind_voice` (X/Y/Z map) |

Each criterion is `PASS | FAIL | PENDING`. Provider status: all PASS → `PASS`; only #4 FAIL →
`TUNE_LATENCY`; any FAIL → `FAIL`; else `PENDING`.

**Decision:** passers ordered by `provider_priority` (`[C, A, B]`, team decision; PDF: `[A, C, B]`) → winner. A provider ranked above all undecided ones wins immediately, so a C pass needs no A/B calls. Cost per minute is shown
for every passer; if a lower-priority passer is cheaper by ≥ `cost_close_pct`, the summary flags it for
a human call. No passer: any `TUNE_LATENCY` → "tune and re-test"; any `PENDING` → "incomplete"; else
**"STOP — update Mishlav"**. Output: console + `results/summary.md`.

## 9. Deviations from the PDF

1. **`end_call.reason` (optional, closed list).** Without it the log can't distinguish `DO_NOT_CALL`,
   `VOICEMAIL` and `NOT_INTERESTED`, and the spec requires scoring from the log. It's harmless in
   production: the model proposes, the backend validates.
2. **`request_human.name/phone` (test only).** Scenario 3 checks the dictated phone digit-by-digit.
   Controlled by `testing.capture_dictated_details`; must be `false` in production, where 4.2 forbids a
   phone parameter.
3. **Provider order C → A → B.** Team decision: Gemini Live is tested first and has top priority
   (`testing.scoring.provider_priority: [C, A, B]`). The PDF had A → C → B.

## 10. Security in Part 1

- Shared secret on every non-health route, from day one; secret only in `.env` (git-ignored).
- Strict tool schemas; unknown fields rejected and logged.
- Card-number redaction before anything is written to disk.
- No real SMS, no DB, no personal data — the log holds only tool params.
- ngrok URL is not secret; the shared secret is what protects the server.

## 11. Later phases (outline)

**Part 3 — order C → A → B.** C first: `apps/voice-worker` (Python, LiveKit Agents) with Gemini
`RealtimeModel` (`gemini-3.8-live`), `X-Provider: C`, `X-Call-Id: <room name>`; B later reuses it via
`VOICE_PROVIDER=soniox_eleven`. The worker's function tools POST to the same server; per-turn metrics
from LiveKit are posted to `/test/metrics`. A: configure webhooks to `https://<ngrok>/tools/<name>`
with secret header + `X-Call-Id: {{system__conversation_id}}` + `X-Provider: A`.

**Part 4 (shared).** Supabase schema: `contacts, phones, dial_queue, call_attempts, call_results,
block_list, imports, exports, audit_log`; RLS on all; three projects. Dialer: `SELECT … FOR UPDATE SKIP
LOCKED` claim, concurrency ≤ 20 with backoff, block-list check + `call_id → contact_id` insert before
dial, retry rules from `settings.dialing`, kill switch. Tools API: same routes, real logic, identity from
`call_id`, `[BOT]` notes, credit-card deletion. Export feed: `GET /export?since=` with API key.
Notifier: WhatsApp/email on `HOT_LEAD`/`COMPANY`. `MockProvider` implements `VoiceProvider` with
scripted outcomes and delays.

**Branches.** A: `ElevenLabsAgentsProvider` (outbound API, post-call webhook with HMAC verification),
agent-as-code via ElevenLabs CLI. B/C: `LiveKitProvider` (`CreateSIPParticipant` via Voice Center
outbound trunk), production worker, post-call LLM extraction into `CallResult`.
